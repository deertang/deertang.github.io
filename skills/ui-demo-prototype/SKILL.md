# 产品UI与演示Demo

## 目标
用可用性与平台规范提升UI质量，并用结构化脚本提升Demo表达效率。

## 关键输入
- Demo目标（验证/沟通/售前/对齐）
- 目标用户与关键场景
- 现有原型或UI稿

## 核心流程（建议 3-6 步）
1. 明确Demo目的与关键故事线
2. 选择原型保真度与工具（低/中/高保真）
3. 进行UI可用性评审（启发式清单）
4. 按平台规范校验关键交互与视觉一致性
5. 输出Demo脚本与问题清单并迭代

## 判断方法
- 使用通用可用性启发式进行问题扫描
- 对照平台级设计规范避免违背系统体验
- Demo强调用户价值与关键流程，不堆功能

## 输出格式
- Demo脚本（故事线 + 关键步骤）
- UI问题清单（严重度分级）
- 原型改进建议与优先级

## 常见坑
- Demo只讲功能不讲用户价值
- 交互与平台规范冲突
- 过度追求美观而忽视可用性
