# MVP范围定义

## 目标
用尽可能小的投入获取尽可能大的验证学习，明确MVP边界与验证路径。

## 关键输入
- 机会/问题陈述
- 目标用户与场景
- 约束（时间、资源、依赖）
- 需要被验证的核心假设

## 核心流程（建议 3-6 步）
1. 明确要验证的核心假设（价值、可用性、可行性）
2. 设定学习目标与成功阈值（可观察、可验证）
3. 划定最小功能集：必须/可延后/不做
4. 设计最小验证方式（原型、手工流程、试点）
5. 输出范围边界、验证计划与下一步决策点

## 判断方法
- 是否最大化“学习”，而不只是最小化“功能”
- 是否能在最短周期获取关键反馈
- 是否避免把 PoC/原型当作MVP
- 是否把“最小”做成“可用且可信”的最小体验

## 输出格式
- MVP范围清单（必须/可延后/不做）
- 验证计划（假设、方法、指标、时间）
- 风险与依赖清单

## 常见坑
- 只做功能，不定义学习目标
- 把简陋体验当成最小可行
- MVP范围不断膨胀，失去验证节奏
